# 主机目录归属样板

[host-foundation-example.json](host-foundation-example.json) 可整体粘贴到组件页“批量导入”，预检并确认后创建两个草稿。导入不会发布、执行或替换现有组件。

- **主机基础目录样板**：L1 组件，公开字符串参数 `shared_root` 由环境 Owner 提供。负责检查、创建并验收自己管理的目录。
- **共享目录消费样板**：精确依赖第一个组件，通过公开参数映射得到 `prepared_root`，并在实际目标主机上检查目录。参数传递不会替代跨主机可用性检查。

目录限制在 `/tmp/clusterforge-foundation-example-<唯一后缀>`，以非提权方式运行。安装前记录目录原本是否存在、设备号、inode 和平台恢复元数据；重试不覆盖原始基线。已有目录和业务内容保留，符号链接与被替换的目录会阻断。下游创建带恢复身份的消费标记；下游先回退后，上游才可删除其亲自创建的空目录。上游不递归删除，也不接管已有目录的权限。检查阶段独立读取实际状态。

简单的共享路径字符串约定可继续使用现有受治理环境变量；组件私有目录仍由所属组件参数管理。只有实际负责准备资源的组件才作为依赖。这个样板不把所有操作系统信息和目录都集中成一个万能组件，也不自动改绑已有组件的目录。

本地回归使用 PyYAML 和 Ansible：

```sh
ANSIBLE_PLAYBOOK=/absolute/ansible-playbook python3 scripts/test-host-foundation-example.py
```

命令从项目根目录执行，只在 localhost 创建唯一临时目录，验证首次安装、重复安装、下游阻止上游回退、逆序回退、已有数据保留、inode 替换与符号链接拒绝；日志保留在输出的临时目录。当前样板已在 Ansible 2.18.6 下验证。适配其他 Ansible/Python、真实主机组、权限模型及实际业务目录，须单独测试后采用；不能直接把这个临时目录样板视为已有集群验收证据。
