# 首版与环境策略

> 当前项目版本：首个版本（V1）
> 当前运行环境：测试环境，不是生产环境
> 文档基线：2026-09-07 代码审核后的工作区

在出现标题明确标注“第二个版本”或“V2”的文档之前，仓库中的代码、API、数据库结构、示例、部署说明和其他文档一律按首个版本解释。

首版只维护一个当前合同，不提供通用历史兼容：

- 默认不兼容、不回填历史数据库或历史数据；空库按当前 `internal/store/schema.sql` 初始化。
- 运行时代码和常规部署只接受当前 `schema_contract`，不包含前序合同迁移、模糊匹配、自动推断、双读或双写。
- 其他合同一律失败关闭；需要继续使用时先备份，再按当前合同显式重建测试数据库。显式授权的场景生命周期离线转换见下文。
- API 只接受和返回当前 camelCase 合同，不接受旧字段别名、snake_case 别名、双读或自动转换。
- 测试环境中的数据、账号、凭据引用、地址和部署结果都不能作为生产数据或生产验收证据。
- 组件 Release、场景 Revision、环境 Revision、回滚和废弃是首版业务能力，不表示平台需要兼容历史版本数据。

测试数据库已按授权删除且服务处于 `inactive` 时，使用 `./scripts/deploy-test-88-55.sh --initialize-empty-db` 部署当前工作区并初始化新库；保留账号与基础目录，业务目录为空。该入口拒绝任何已有数据库、SQLite 辅助文件或符号链接，不能与重建或活动 Run 覆盖参数组合。部署前保存程序和配置，失败恢复原程序、配置以及停服无库状态。若 Git Catalog 备份已明确停用，同时传入 `--disable-catalog-backup`；原有数据库备份保持原样。

明确授权的业务重置是限定例外：`database foundation-snapshot` 读取旧 V1 库，按当前 schema 新建数据库，只复制账号、平台分类/选项及环境变量字段定义。旧业务、Run、会话、测试证据、已停用的全局参数默认值和自动保留策略不进入新库；不修改源库，不恢复旧业务合同。源库缺少必需目录字段或目录不满足当前约束时拒绝转换。具体流程见[业务清空专用备份](catalog-backup-and-restore.md#业务清空专用备份不含-run-历史)。

此前明确授权的场景生命周期转换是另一项限定例外（不构成新环境的操作授权）：`database convert-scenario-lifecycle` 从精确的 `clusterforge-v1-20260905-role-jobs` 合同生成当前合同的新库。源库还必须已经具有符合当前规则的固定分支范围；仅匹配旧合同不足以执行。满足前置检查后，工具完整保留业务、Run 历史和旧摘要，复制独立工作区并验证源不变。它不回填来源或验收证据，不修改源库，不扩大运行时支持的合同集合。操作方法见[场景生命周期](scenario-lifecycle.md#保留历史的离线数据库转换)。

只有新增第二个版本文档后，才允许设计通用跨版本迁移、兼容窗口和数据升级策略；届时必须在 V2 文档中显式列出来源版本、目标版本、保留期限、验证和回退方案。

发生冲突时，首版数据库结构以 `internal/store/schema.sql` 和 `schemaContract` 为准，HTTP 路由以 `internal/api/handler.go` 为准，业务与权限以 `internal/service` 及其测试为准；发现文档落后时直接修正文档。文档职责和维护入口见[文档中心](README.md)。
