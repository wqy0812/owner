## 平台定位与使用范围

ClusterForge 将可复用的 Ansible 作业组织为组件版本，再通过场景编排到指定环境执行。平台保存版本、计划、审批与运行证据，让各类 Owner 能够共同维护和交付集群。

当前为首个版本（V1）的单实例测试平台，使用演示身份切换。前端面向桌面浏览器，工作区最小宽度为 1280 CSS 像素；较小窗口沿用桌面布局并横向滚动。可以手动收起左侧导航，为编排画布和表格腾出空间。

## 核心对象与关系

- **Component / 组件**：一项可复用的软件能力，保存名称、分类和归属。组件下可以有多条独立发布线。
- **Release Line / 发布线**：同一安装与演进基线。创建时确定固定适配标签；全新发布线独立建立基线；沿现有发布线演进时明确父版本、升级和回退关系。
- **Release / 组件版本**：锁定精确依赖、参数权限、适配范围、生命周期动作、Playbook 工作区及介质和镜像身份。Draft 可编辑，已发布版本不可原地修改。
- **Scenario Revision / 场景版本**：锁定精确组件、完整目标配置、业务验收作业及其参数和文件。派生版本另外记录升级来源和顺序；分支场景独立保存模板来源。依赖边由合同生成，手工顺序不能违反依赖或产生环。
- **Environment Revision / 环境版本**：保存某一时刻的主机、主机组、实际适配标签、组件环境参数、变量和凭据引用。保存修改生成新 Revision，历史快照可用于创建新版本。
- **Run / 运行**：一次组件验证、场景测试、正式场景运行或环境回滚。提交时锁定版本、解析参数和文件摘要，随后编辑资产不会改变该次执行。

场景节点是逻辑作业，环境节点是实际主机，两者不需要数量相等。执行对象应以 Run 的最终步骤、Action 与主机组为准。

## 我的工作

工作台按当前角色实时汇总阻塞交付、等待处理、进行中和待评估影响，并提供到具体组件、场景、环境或 Run 的入口。工作项来自当前业务状态和证据，无需另建任务或手工关闭。

平台 Owner 在工作台处理组件合同审核。组件 Owner 关注自己版本的合同、证据和发布缺口；集群 Owner 关注编排、完整测试和发布；环境 Owner 关注配置、审批、运行和灾备状态。

## 组件与版本管理

组件目录支持 L1–L6 分层检索、新建组件、批量导入、“新增分支”“新增版本”和版本详情。适配标签在首行展示，创建分支后固定；参数与直接依赖各自编辑、分别原子保存，过期页面提交会被拒绝。组件 Owner 定义参数的公开性、可修改性和值提供方；下游只通过精确上游版本引用公开参数。

每个 Release 的 Playbook 是一个受管理的版本工作区，包含固定动作入口和所需的模板、Role、脚本与辅助文件。Draft 支持上传、在线编辑及文件管理；大型安装介质走文件站，镜像按内容摘要登记或构建。

发布就绪度综合当前合同审核、动作、依赖和成功验证证据。审核批准、测试成功、加入候选和正式发布是不同阶段。合同或工作区改变后，旧审核、候选状态和测试证据会失效。

“谁用了我”按精确 Release 展示已保存的直接组件依赖和场景引用，并提供历史筛选；它用于评估变更影响，不等于递归展示所有间接使用方。无详情权限的私有引用只展示摘要。“Run 证据”用于追溯组件验证及锁定该版本的场景执行记录。

## 场景编排与发布

新建场景为空白分支，已发布版本提供“新增分支”，允许从其他 Owner 的可见版本复制。分支创建时确认适配标签，之后只读；“新增版本”沿用当前分支范围。分支由创建者独立维护，从 r1 Draft 开始，复制配置与验收工作区，保留来源跳转；不继承测试证据、升级关系或环境安装基线，也不能跨场景升级。

同场景“新建版本”要求来源仍已发布，并有通过全部组件检查和业务验收的成功正式安装或升级 Run。仅测试成功、已废弃或缺少业务验收的历史版本不能作为演进来源；历史已发布版本仍可作为分支模板，在新场景补齐验收。

场景页以“目标集群”“升级作业”“业务验收”组织工作。集群 Owner 选择精确 Released 或已共享候选 Draft，通过 DAG、节点表和参数总览维护目标配置；“更换组件版本”保留有效参数并提示失效字段和依赖。组件主机组由合同决定，依赖边自动生成，存在歧义时须明确参数来源或补充合法顺序。

每个新版本至少配置一项有序 Ansible 业务验收，支持在线编辑、上传、辅助文件和类型化参数绑定。作业按顺序自动执行，临时资源清理失败也算失败，任一失败立即停止并保留现场。全部自动通过即完成验收，无需人工签字。未发布版本在没有相关活动 Run 时可继续编辑同一 Revision，修改会使旧测试证据失效。

首版需要干净环境安装测试；同场景派生版本同时需要安装和升级测试。升级测试及正式升级都要求目标环境实际处于来源完整版本，并与该环境自己的正式基线 Run、组件安装记录及参数匹配。安装和升级最后均检查完整目标集群并执行全部业务验收；升级只执行变化项，不重装未变化组件。

创建分支、新建版本和执行均先预览再提交；执行请求锁定摘要并防止重复提交，环境或计划变化后须重新预览。页面分别展示两类测试证据及发布阻塞原因，发布事务复核证据、当前内容和候选合同后原子发布。发布不会自动变更集群，正式安装或升级仍须单独选择环境、预览和提交。当前只支持直接来源到目标，不支持跨级、跨场景迁移、主机迁移或扩缩容。

## 环境与主机管理

组件环境字段显示组件、分支、精确版本和当前环境 Revision。凭据显示受权限控制的动作或验收声明来源及填写状态；不解析 Secret，也不将声明误作实际运行证据。

环境 Owner 管理 Inventory 主机、主机组成员、适配标签、组件环境参数、非敏感变量与 CredentialRef。主机组管理先在弹窗应用，再保存环境新 Revision；取消编辑不会改动已保存的 Inventory。

组件与场景声明多选支持范围，环境填写单选实际值。同类多个标签取或，不同类别取且；场景范围必须被所有组件支持，环境必须匹配场景和组件要求。缺项可以暂存草稿，明确冲突不能保存；测试、发布和执行要求完整匹配。Docker/containerd 通过精确组件依赖表达。

环境参数字段来自组件合同，按精确 Release 和参数名保存；环境 Owner 只能填写分配给环境的字段。平台不提供全局环境参数默认值入口。凭据仅保存引用，实际秘密在执行时解析并脱敏。

连通性入口分别给出 TCP 和 SSH 检查结果，不能替代 Playbook 执行验证。环境支持历史 Revision 查看、导入导出和基于历史创建新 Revision；环境归档、删除和整集群回滚均受活动 Run、安装基线及历史引用限制。

## 运行、审批与日志

运行中心按当前记录、历史归档、状态和环境筛选，并分页读取摘要；选中记录后加载步骤、审批、参数来源、备份信息和日志。单环境按 FIFO 串行执行，不同环境可以并行。

危险动作、删除组件以及需要确认的介质或镜像交付先等待目标环境 Owner 审批。批准后才进入执行队列；批量审批仍检查每条记录的权限和当前状态。允许安全续跑的组件等 Run 仍须验证版本、环境及文件指纹；场景安装或升级失败不能直接进入通用续跑。

场景发生变更后失败、取消或中断，环境保留部分变更和恢复备份；恢复后须复核实际基线。基线复核不交付新介质，不替代发布测试或正式运行证据，也不把测试部署转为正式部署。新增节点须先证明清理或卸载，不能只验证旧节点后放行。含场景升级历史的环境不能通过整集群清空入口把“恢复旧版本”记为“已清空”。

在线日志显示当前已加载的末尾最多 200 行，支持搜索、流筛选和复制。下载已加载日志不等于导出整个 Run 的全部日志；成功归档后的下载包包含完整保留日志、执行快照、步骤和审批。

平台 Owner 可以归档成功 Run，预览并清理超过保留期且不受安装、续跑或回滚引用保护的失败 Run。自动归档和清理初始关闭。成功归档保留业务证据，失败清理不可恢复；取消、拒绝、中断和活动记录不属于失败清理范围。

## 通知与影响追踪

通知中心汇总上游版本发布造成的影响，支持查看关联资源和标记已读。演进通知针对精确引用父 Release 的对象，不会自动把下游升级为最新版本。标记已读只表示已确认通知，不代表已完成升级、测试或发布。

## 平台治理与审核

环境变量字段、环境适配维度、主机组分区维护。“新增类别”位于适配维度区域；真实父子类别同框独占一行，“新增子类别”预选当前父类别。已有独立类别不按名称自动合并。

平台管理仅向平台 Owner 开放，用于维护环境维度类别、选项和非敏感环境变量字段。主机组属于系统保护类别；历史引用和事务校验限制可删除的目录项。

合同审核从“我的工作”进入，预览当前参数权限、动作和实际 Playbook 内容后批准或驳回。批准只针对当时的内容摘要。平台 Owner 还负责运行历史策略，但不会替代组件 Owner 发布版本或替代环境 Owner 审批危险 Run。

## 灾备与恢复

环境 Owner 通过灾备目录接入私有 Catalog 仓库、创建恢复点和预览空库恢复。是否可备份取决于服务配置、仓库和调度状态。

Catalog Git 保存已发布定义和对应 Playbook，用于恢复发布目录；完整历史恢复需要 SQLite 一致快照与对应 Run 归档文件。仅恢复 Catalog 不会恢复完整 Run 历史，单独复制数据库也不能还原已归档日志。

## 版本切换与协作约束

平台检测到新的前端构建后会提示刷新，旧页面的写操作被阻断。刷新前保存或记录未提交表单，刷新后重新预览执行计划和审批内容。

页面展示遵循当前身份和对象状态，最终写权限、摘要校验和状态转换由后端判定。SSE 只是刷新提示，最新读取的后端记录才是状态依据。详细按钮、操作条件与交接步骤见说明书中的工作流、角色手册和部署章节。
