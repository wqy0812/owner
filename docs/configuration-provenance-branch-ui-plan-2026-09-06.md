# 配置来源、分支适配标签与管理界面实施方案

> 日期：2026-09-06。状态：本地实施与验证完成，结果见[验证记录](records/2026-09-06-configuration-provenance-branch-ui-validation.md)；后续本地提交见 [2026-09-07 分批审核](records/2026-09-07-batched-code-review.md)，未部署。
> 适用范围：ClusterForge 首版 V1；遵循[首版与环境策略](version-policy.md)。本方案本身不执行业务数据变更或测试环境重建。

## 1. 目标与确定口径

本次改造解决七个问题：配置来源不清、平台类别关系不直观、分支与版本入口混杂、目录归属不明确、合同编辑范围混杂、介质与镜像弹窗比例失衡、执行阶段计数公式占用界面。

| 事项 | 实施口径 |
| --- | --- |
| CredentialRef 来源 | 同时展示需求声明来源、引用类型、配置状态；凭据引用继续遵守现有权限与脱敏规则 |
| 组件环境参数来源 | 展示所属组件、分支、精确版本、参数名，以及当前值所在的环境 Revision |
| 环境维度目录 | 类别新增入口与已有类别归入同一区域；父子类别同框、独占一行；类别内维护选项 |
| 标签位置与锁定 | 场景和组件首行展示适配标签；创建分支时确定，创建成功后固定；新增版本继承 |
| 创建按钮 | 统一为“新增版本”和“新增分支”；Draft 作为状态显示“草稿” |
| 目录组件 | 共享路径约定使用现有受控环境变量；需要创建、权限管理和验收的目录归属主机基础准备组件 |
| 合同编辑 | 去除重复入口；直接依赖与参数合同分别进入编辑，后台共同校验一致性 |
| 介质与镜像弹窗 | 表单为主、结果摘要为辅；构建日志支持独立展开 |
| 执行阶段计数 | 删除“组件阶段 1 + 最终复查 0 + 业务验收 0 = 1 步”及同类数量分解公式 |

“新增分支不允许改”在本方案中解释为：**创建分支时可以选择适配标签，创建成功后不能再改该分支标签；版本草稿内容仍可按现有生命周期编辑。**

固定范围仅包含操作系统、架构、IP 协议族等适配标签。组件自由检索标签、说明、分支显示名继续沿用现有编辑规则，不因本次改造一并冻结。

## 3. 环境配置来源

### 3.1 CredentialRef 的展示

每条凭据展示以下信息：

| 信息 | 展示方式 |
| --- | --- |
| 凭据名称 | 保留稳定名称，例如 `ssh_private_key`；名称是合同引用键 |
| 需求来源 | 组件 / 分支 / 版本 / 动作；场景 / Revision / 业务验收作业；或平台 SSH 检查用途 |
| 引用类型 | “后端环境变量引用”或“后端密钥文件路径”，可保留 `envVarRef`、`sshKeyPath` 作为辅助说明 |
| 配置状态 | 仅报告现有证据能证明的“已填写引用 / 未填写引用”；实际可用性沿用现有检查结果 |
| 值所在位置 | 当前查看的环境与 Revision；引用字符串按现有角色权限展示 |

来源从组件 Action 的 `requiredCredentials`、场景业务验收的凭据声明、现有平台 SSH 配置合同汇总，不解析或展示真实 Secret，不为展示来源读取后端变量值或密钥文件内容。

同一凭据可以被多个来源引用：按精确版本、动作或验收作业去重后完整列出，数量多时折叠。平台内置来源应使用稳定用途类型，不伪装成某个组件。

必须区分“目录中声明了这个凭据”和“该环境的特定运行实际使用过这个凭据”。无运行或安装记录时，只显示声明来源，不声称已在当前环境使用。

不把全平台所有组件的凭据需求都标成当前环境必填，不自动创建空引用。无可见声明时显示“暂无可见声明来源”，不能据此认定可以删除；已有历史引用继续保留。

### 3.2 组件环境参数的展示

字段采用以下结构：

> 参数名 · 必填 / 可选
>
> 定义来源：组件名称 → 分支 → 版本 → 参数合同
>
> 当前值：环境名称 · rN；下方为输入框及建议值操作

保留类型、描述、必填、建议值等现有合同信息。来源链接定位到精确 Release 的参数区域，不能跳到该组件最新版本。

相同参数名在不同版本中仍是不同字段，不按显示名合并或跨版本套用值。历史已发布但已废弃版本的参数，继续按当前可运行历史合同维护。

本次显示“值存在哪个环境 Revision”，不新增完整的值编辑溯源系统。现有数据不能区分“手工填了与建议值相同的值”和“点击采用建议值”，因此不凭值相等推断填写方式。

### 3.3 后端与前端分工

- 由 EnvironmentService 统一提供来源摘要；复用现有组件环境字段接口，补充分支 ID、名称、参数定位信息。CredentialRef 来源可增加独立只读查询，具体路由在实现时同步登记到后端 API 文档。
- 查询显式接收当前用户和目标环境 / Revision，沿用已有环境查看权限及合同可见性；受限来源返回允许查看的摘要，不泄露未共享草稿内容或生成无法访问的链接。
- 来源返回稳定 ID、来源类型及显示字段，跳转由前端现有路由构造；组件、场景和凭据变动后触发对应来源数据刷新。
- 后端批量读取、聚合和排序；前端不得为每条凭据逐个请求全量组件合同。分页或折叠展示不得丢失来源计数。
- 初次加载、刷新失败与空列表区分展示，查询失败时不能把已有来源清成“无引用”。

## 4. 平台类别目录

页面保留三个清晰区域：“环境变量字段”“环境适配维度”“主机组”。类别和选项使用统一术语，避免把适配选项称为变量。

“环境适配维度”区域标题提供“新增类别”。默认展示已有类别，创建表单按需展开；创建成功后定位新类别，并展示新增选项入口。

父类别卡片内提供“新增子类别”，自动绑定当前父类别；用户不必在远离当前卡片的表单里重复选择父类别。创建前明确展示目标关系。

父子组使用如下结构，整组占一行：

```text
操作系统 → 操作系统版本                 [新增子类别]
Ubuntu     22.04 / 24.04                [新增 Ubuntu 版本]
SUSE       已关联的版本选项              [新增 SUSE 版本]
                                      [新增操作系统]
```

普通无子类别的维度仍可两列排列。父选项及其子选项保持同一视觉分组；未关联、已退役、被历史使用等状态继续可见，保留现有退役与删除保护。

数据关系同时包含 `parentCategoryId` 和 `parentOptionId`。新增子类别并不意味着现有子选项可以自动归到某个父选项。

初始化目录按明确关系提供父子数据。对于已有独立根类别，实施前生成类别与选项关系清单，识别混合值和不明确归属；不按名称自动关联、不改写已发布版本或环境历史快照。数据库处理沿用第 9 节的 V1 边界。

## 5. 分支、版本与适配标签

### 5.1 对象和持久化

组件继续使用现有 `ComponentReleaseLine` 作为分支；场景继续使用现有独立 `Scenario` 作为分支工作区，分叉保持当前来源关系。本次不另建通用分支服务或重做场景对象层级。

为组件发布线、场景对象分别保存固定的 `environmentConstraints`。创建首版时确定分支范围，后续 Release / Revision 保存相同范围的版本快照。分支定义是新版本创建依据，版本快照继续参与现有摘要、适配校验及 Run 锁定。

服务端与持久化写入共同确保：

1. 分支与首个草稿原子创建，二者标签相同。
2. 新增版本从所属分支读取标签；请求不提供可覆盖字段。
3. 所有版本编辑、导入、复制、恢复、重新打开草稿等入口都不能改变所属分支范围。
4. 保留标签字段的完整合同写入入口必须比较规范化后的语义值；不一致时拒绝，并提示“适配范围已固定，请新增分支”。不得静默忽略更改。
5. 并发保存及发布事务仍复核当前状态和摘要；标签顺序变化、重复值不应被误判为范围变化。

分支显示名与身份 ID 分离。名称编辑继续遵守现有状态、工作区路径和引用约束；显示名变化不得改变分支身份或适配范围。

### 5.2 创建交互

| 入口 | 表单内容 | 创建结果 |
| --- | --- | --- |
| 新建组件后的首个版本 | 首分支名称、初始版本、适配范围、说明 | 一个分支与其首个草稿 |
| 组件 / 新增分支 | 分支名称、初始版本、可选内容模板、适配范围 | 独立发布线，不建立跨线升级关系 |
| 组件 / 新增版本 | 当前分支、可用来源、目标版本、升级兼容性；标签只读 | 当前分支后继草稿 |
| 空白新建场景 | 名称、标识、说明、适配范围 | 独立场景与 r1 草稿 |
| 场景 / 新增分支 | 来源已发布版本、新场景身份、适配范围 | 独立场景与 r1 草稿 |
| 场景 / 新增版本 | 当前场景、精确来源版本及成功正式 Run；标签只读 | 当前场景后继 Revision |

“新增版本”“新增分支”进入固定用途的表单，不再进入后通过“创建方式”切换语义。没有可演进基线或已有活动草稿时，新增版本禁用并展示具体原因；新增分支按既有权限与来源规则判断。

新分支可从模板预填标签，但 Owner 必须在创建预览中确认；切换模板不能悄悄覆盖手工选择。预览展示源范围和目标范围，目标范围参与 `planDigest`，提交时重新校验。

保留当前“未限定某维度”的匹配语义，但创建表单应将它明确显示为“不限制”，与“尚未完成选择”区分。创建预览须把未限制维度列清，不自动按组件集合或平台目录替 Owner 选择范围。

新分支改变范围后，复制来的组件可能不匹配。允许保存为待调整草稿，明确列出冲突；完成组件替换和校验前阻止测试、发布和运行，不静默替换组件或缩小范围。

同一分支支持范围扩大或缩小均通过新增分支完成。此规则会增加分支数量，是本次固定适配范围的明确取舍。

### 5.3 首行展示

- 场景首行展示当前场景 / 分支、版本、草稿或发布状态及实际标签值，替换原先只显示“适配标签 N 类”的主要入口。
- 组件详情首行展示当前选中分支、版本、状态和标签；切换发布历史时同步更新，不能仍展示最新版本标签。
- 标签过多时使用“其余 N 项”展开完整范围，保持创建按钮可达；支持桌面布局，不增加移动端改造。
- 原场景设置、组件版本与 Playbook 弹窗中的标签输入改为只读摘要或移除重复展示，避免留有第二个可修改入口。
- 用户可见的创建文案改为“新增版本 / 新增分支”，草稿状态统一中文；内部 Draft 枚举和已有 API 业务术语不作无意义改名。

### 5.4 保留既有生命周期门禁

新增版本不等于发布，不继承来源的测试通过状态。

组件保留同发布线最新已发布基线、单活动草稿、精确父版本和已有发布验证规则。场景保留“已发布且成功正式安装或升级 Run 通过全部业务验收”的演进条件；新版本仍要求安装与升级测试。

分支只复制配置和独立工作区，不继承测试证据、发布状态、环境安装基线或来源场景升级资格。标签相同也不代表可以复用证据。

## 6. 合同编辑入口与保存边界

### 6.1 入口整理

删除发布历史中的“配置合同”、查看详情中的“编辑可见性与映射”。组件头部的“编辑依赖和参数”也统一引导到具体区域，避免继续保留一个同时打开两区的编辑入口。

保留各区域独立的“编辑”按钮；发布就绪度等辅助入口可以定位对应区域，但必须携带明确编辑意图。Playbook 入口仅承担版本信息与作业编辑，移除其中重复的参数、依赖和可修改适配标签编辑器。

### 6.2 编辑规则

| 编辑区 | 允许编辑 | 其他区域 |
| --- | --- | --- |
| 直接依赖 | 上游精确版本、依赖用途、公开参数映射 | 参数合同保持只读 |
| 参数合同 | 本组件参数定义、类型、可见性、提供者及约束 | 直接依赖保持只读 |

每个区域有自己的保存与取消，不因点击编辑而让另一个区域进入编辑状态。切换区域或版本前处理当前未保存更改。

需要处理一个现有合同限制：上游映射参数必须有唯一映射，不能先保存一个没有映射的参数，再到另一区域补线。因此提供明确的“新增引用参数”小表单，由用户主动打开，在一次保存中创建目标参数及其映射；不自动展开完整参数编辑页。

参数改名、改类型、删除或改变提供者可能破坏现有映射与 Action / 场景使用。默认给出具体引用和处理入口，禁止静默删除映射。删除依赖或映射时，同样列出将失去来源的参数；用户明确处理关联参数后才能保存。只有合同现有规则允许的关联变更才可一次提交，不能为拆界面放松引用校验。

### 6.3 保存协议

按区域提交变更及预期合同摘要。后台从当前持久合同读取未编辑部分，在同一事务中合并、校验和保存；过期摘要拒绝保存，防止参数编辑覆盖另一次依赖修改。

复用既有合同业务服务，避免两套相互分叉的验证逻辑。接口采用清晰的区域命令或补丁结构，禁止由前端用旧全量合同回写未编辑区域。跨区的“新增引用参数”等操作使用显式关联变更命令。

合同变更继续触发现有审核与验证失效规则，历史 Run 记录保持原样。独立编辑不等于免除发布前共同校验。

## 7. 弹窗与执行摘要

### 7.1 组件介质与构建镜像弹窗

- 桌面左右布局目标约为表单 60%–65%、摘要 35%–40%，由内容和最小可用宽度约束，避免仅缩小整个弹窗。
- 表单输入控件保证完整可用；长 URL、路径、SHA、Digest 在结果区换行或提供复制，不撑开弹窗。
- 空介质、空镜像、暂无构建记录使用紧凑空状态，不占固定大高度。
- 构建日志在下方通栏展示或由用户展开，保留滚动、错误和进行中状态；不能因缩右栏损失日志可读性。
- 已发布版本没有上传 / 构建表单时，让内容与来源修复区使用有效宽度，不留空白左栏。
- 保持上传校验、构建、取消、来源修复与内容身份保护行为，仅调整布局和区域呈现。

### 7.2 删除执行阶段计数公式

删除“组件阶段 1 + 最终复查 0 + 业务验收 0 = 1 步”及类似展示，包括不同计数、非零验收数量和历史 Run 使用计数回退逻辑生成的同类公式。不只隐藏为零的项，也不替换成一排同义统计卡片。

已定位的入口是 [JobPlanPreview](../web/src/components/JobPlanPreview.tsx) 内的 `PlanPurposeCounts`，以及 [RunsPage](../web/src/pages/RunsPage.tsx) 的直接调用。实施时检索所有调用方，覆盖使用共用计划预览的组件测试、场景执行与相关回退 / 续跑预览，再检查运行详情。

清理专用组件、只服务于公式的辅助函数、导入、样式和留白。步骤列表、步骤状态、失败原因与真实执行顺序继续正常展示；本次不删除实际检查或业务验收，也不改变步骤计算、运行快照和成功判定。

作业包范围等位置单独展示的“共 N 步”不属于相加公式，本次不扩大为删除全部步骤数量。后台 `purposeCounts` 若仍被作业包范围等功能消费，继续保留，不为删除展示而改变 API 或历史数据合同。

## 8. 目录归属与主机基础准备组件

### 8.1 目录分类

| 目录用途 | 建议归属 | 是否建立组件依赖 |
| --- | --- | --- |
| 多组件共用的安装根路径等字符串约定 | 现有平台环境变量字段目录，Environment Owner 按 Revision 填写 | 仅共享值不建边 |
| 只属于单个组件的数据、配置目录 | 该组件参数合同，按需交由环境 Owner 填写 | 不凭目录字段增加依赖 |
| 需要创建、属主权限、挂载可用性和验收的基础目录 | L1 主机基础准备组件 | 依赖其准备结果的组件声明精确上游依赖 |
| 操作系统名称、版本、架构 | 环境实际 Facts 与分支适配标签 | 不因标签本身生成执行依赖 |

当前实现的组件环境参数仅支持按版本隔离的字段，本方案不恢复已停用的旧全局环境参数绑定机制。共享非敏感字符串约定使用现有环境变量目录，并核对实际 Playbook 消费与变量冲突规则。

### 8.2 主机基础准备组件的合同

建议名称为“主机基础准备”，避免使用户误以为平台负责安装或升级操作系统。

- 公开安装根路径、共享目录等必要参数；参数提供者、是否可修改、目标主机组由组件合同明确声明。
- 安装动作负责必要的目录准备和权限设置；绑定前置检查与后置验收，确认实际主机上的路径、类型、权限和挂载状态。
- 下游只引用公开参数，锁定精确 Release，并在场景中选择对应上游节点；合同依赖生成执行边。
- 传递路径不等于在任意主机上创建过目录。需要准备的目标主机必须被上游动作覆盖；跨主机组场景在组件检查中验证目标主机条件，不能仅凭已有依赖判定目录可用。
- 默认保留预先存在的目录和用户数据。回退仅处理可证明由该次作业创建、且无下游仍使用的资源，不递归删除系统目录、共享根目录或非空业务数据目录。
- 升级路径、权限或挂载策略属于实际执行变化，重新验证；不能用改公开变量的方式绕过下游影响。

本批先交付目录归属清单及组件合同 / 作业样板。现有组件全面接入、真实目录创建与回退验收作为单独的数据和环境实施批次，具体路径与资源归属以实查为准，不在方案阶段填写虚构值。

### V1 数据库与既有记录

分支范围持久化涉及当前 schema 合同更新，同步初始化、备份 / 恢复、导入导出和 DTO。运行时只接受新的当前合同，不添加通用迁移、兼容读写或按最新版本自动回填。

已有分支可能在不同版本中保存不同范围，不能选任一版本覆盖全分支；目录父子关系也可能不明确。先输出冲突清单，按当前 V1 策略安排数据处理。现有文档中获准的专项离线转换，不自动扩展为本次转换授权。

开发回归使用独立新库及测试工作区。任何测试环境重建、目录调整、业务组件录入和实际主机执行均作为后续明确的数据 / 环境交付事项；本次形成方案不执行这些操作。
