# 四项性能与场景编辑问题验收记录

完成于 2026-09-07，本记录只代表当前工作区的本地隔离验收。未提交、未部署、未重建现有测试环境，未执行真实集群作业。测试包含工作区已有修改，本轮没有撤销或拆分这些修改。

## 实施结果

1. 场景保存和修改判定共用持久化内容转换；展示字段及键顺序不产生修改，真实内容变化仍被检测。服务器响应建立基线，保存期间的新编辑和切换 Revision 后的编辑均保留，继续使用 `expectedDigest`。
2. 新增当前等待状态表，日志插入触发器同事务维护；终态、归档、删除同步清理。新增同一数据库快照的 activity 接口，普通详情不再装配日志或等待项。
3. 日志通知只含 Run ID 和日志 ID，按 Run 分发；400 毫秒合并、单请求在途、游标补拉、去重、可见页面 10 秒补读、2000 条浏览器上限。
4. 工作台改为按角色选择候选和批量读取所需合同，沿用现有业务判定；场景证据分批核验且没有历史数量截断。保留清理标记以压制旧失败。

当前数据库合同为 `clusterforge-v1-20260906-workbench-run-observations`。本轮没有增加旧库迁移、历史回填或兼容读取分支。详细合同见 [活动读取与工作台说明](../run-activity-and-workbench.md)。

## 测量方法

- Apple M2、darwin/arm64，同机同夹具顺序测量；关闭本轮浏览器及临时服务器后执行最终采样。
- 每种路径预热 3 次，再逐次执行 31 个请求，记录单次耗时中位数、P95，以及这些请求的 Go 堆累计分配量除以请求数。
- 工作台旧路径保留在测试专用 `legacyWorkbench` 中，来自改造前的聚合代码；两条路径使用相同数据库和业务判定。等待旧路径使用改造前的 JSON 窗口查询。
- 原规模为 18 个组件、64 个 Release（18 个 Draft）、305 条 Run、1 个场景、1 个环境 Revision。十倍历史夹具为 3050 条 Run、640 个 Release、10 个环境 Revision，当前 Draft 和业务对象数量不变。Run 含约 10 KB 锁定参数。场景为空 Draft，管理员没有待审核项；这些角色的数值不代表复杂场景或大量待审核项的绝对耗时。
- MB 使用十进制。累计分配是 Go 堆分配指标，不是常驻内存，也不等于 SQLite 的全部内部缓冲占用。测量不包含真实网络、浏览器渲染或真实集群执行。

时间单位 ms；每格耗时依次为中位数 / P95，分配依次为旧 / 新。

| 305 / 场景 Owner | 4.227 / 4.558 | 0.597 / 0.732 | 0.982 / 0.030 | 85.9% | 97.0% |
| 305 / 环境 Owner | 26.292 / 28.417 | 2.516 / 2.862 | 17.252 / 0.642 | 90.4% | 96.3% |
| 305 / 平台管理员 | 1.283 / 1.588 | 0.070 / 0.076 | 0.820 / 0.002 | 94.5% | 99.7% |

原规模下，四种角色均达到耗时及累计分配至少下降 50% 的目标。十倍历史下不装配额外历史合同或全量 Run 快照；组件 Owner 分配仅由 2.157 MB 增至 2.205 MB。可见性筛选和最新记录排序仍有随历史数量增加的 CPU 成本，本次没有宣称工作台总体耗时恒定。

原始数据：[工作台 31 次采样统计](2026-09-07-workbench-performance.json)。另有 `BenchmarkWorkbenchReadModels` 可用于重复测量 Go benchmark 指标。

微秒级采样受调度噪声影响，三档新查询未表现出历史扫描式增长。先前独立运行的 100 次 Go benchmark、每档重复 3 轮，新查询为 5.48–6.87 微秒/次、784–785 B/次。执行计划检查要求 `SEARCH run_waiting_observations`，不得访问 `run_logs`，不得使用临时排序树。

## 回归与浏览器验证

- Go 全量及 `go test -race ./...` 通过。最初沙箱禁止测试用本地监听，获得工具授权后用同一隔离测试套件重跑通过。
- 前端 23 个测试文件、238 项测试及生产构建通过。浏览器发现系统日志可省略 `stepId`，已修正客户端规范化并补回归。
- 场景覆盖键顺序、空值、多选集合、参数数组顺序、真实依赖变化、合同延迟、保存失败、保存期间编辑、切换 Revision 和并发冲突。SSE 重连单独验证业务对齐。
- 状态表覆盖重复等待、多主机、结果清除、无效事件、回滚、终态及迟到日志、重开数据库、并发写入下的一致快照、归档和删除。记录器验证落库失败不发事件、提交后仅发 ID。
- 工作台覆盖四种角色的新旧结果对照、Readiness、审批、失效 Candidate、旧成功证据失效、最新记录压制失败及清理不复现旧失败。额外构造 130 条较新的失效成功记录，确认分批搜索仍找到更早的有效证据。

隔离浏览器使用本轮新建的临时 SQLite 和本地 Go API，禁用真实 Ansible。两个活动 Run 和追加日志由夹具写入；日志突发通知注入现有 EventSource，数据读取仍走真实 API。网络故障通过浏览器 offline 模式模拟，没有向其他环境写数据。

| 浏览器场景 | 观测结果 |
|---|---|
| 切换 DAG、节点表、参数总览、选择节点 | 无假修改，测试前保存规则不变 |
| 选中 A，发送 100 条 A 的日志通知 | 1 次 `A/activity?afterId=324`，列表、完整详情、工作台 0 次 |
| 选中 B，发送 100 条 A 的日志通知 | 所有 API 请求 0 次 |

## 复测入口

```sh
go test ./...
go test -race ./...
pnpm --dir web test
pnpm --dir web build
CLUSTERFORGE_WORKBENCH_PERFORMANCE_REPORT=/tmp/workbench.json go test ./internal/service -run '^TestWorkbenchPerformanceSamples$' -count=1
CLUSTERFORGE_WAITING_PERFORMANCE_REPORT=/tmp/waiting.json go test ./internal/store -run '^TestWaitingPerformanceSamples$' -count=1
python3 scripts/check-docs.py
```

性能夹具只在明确设置报告路径时运行；正常回归跳过采样。真实集群、受保护部署和现有测试环境数据库没有作为本轮测试对象。
