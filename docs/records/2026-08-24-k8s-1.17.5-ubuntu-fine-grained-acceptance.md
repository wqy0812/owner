## 前台变更

1. Host Preflight `v1.17.5-u1`

每个 Release 均配置独立托管 Playbook，生命周期为安装、验证、回滚 3/3，并在环境 2 完成安装验证和回滚验证后达到发布门禁 4/4。

初次录入时，前台 Release 的操作系统枚举只有 SUSE 和 Kylin，因此操作系统维度保持“不限制”；每套安装/预检 Playbook 通过 Ansible facts 对 Ubuntu 18.04 AMD64 fail-closed，Docker 动作额外断言 Server 版本必须为 20.10.21。随后平台已补充 Ubuntu、操作系统版本和 Docker 版本三组精确约束，新 Draft 可直接声明 Ubuntu 18.04 / Docker 20.10.21。

## 流程优化（同日补充）

- 增加候选 Release 显式交接：验证完成的 Draft 可加入候选集，场景 Owner 可在发布前编排和完整测试；场景与全部候选 Release 通过单一事务原子发布。
- Draft 交付门禁移到后端：必须存在安装、验证、回退 3/3 动作，并具有当前合同的安装验证和回退验证证据。
- 新 Draft 场景的跨组件硬依赖边必须同时存在 Release 直接依赖合同，避免只靠场景 50 条边表达依赖。
- 组件中心支持细粒度 JSON 模板导入，场景中心支持节点/边模板导入、复制和节点表视图。
- 环境 Owner 可批量批准维护窗口中的危险 Run；整批审批原子提交，执行仍按环境 FIFO 串行。
- 运行日志增加流筛选、全文搜索、匹配行复制、完整日志下载和活动 Run 自动滚动。

新场景名称为 `Kubernetes 1.17.5 Ubuntu 六节点细粒度集群`。r1 包含 21 个执行节点和 50 条硬依赖边，DAG 校验通过，完整场景测试 Run 为 `run-a5be5b5a7faa477aba1fc4c8`，结果成功 100%，随后发布为不可变 Revision。

### 残留修复 1：并发 reset 的 API 注销竞态

- 症状：kubelet 回滚 Run 中 master-5 执行 `kubeadm reset -f` 时，master-4 已关闭 API，`update-cluster-status` 返回 `unexpected EOF`。
- 原因：多个控制面并发 reset 时的 API 注销竞态。
- SSH 修复：仅在 `192.168.88.56` 停止 kubelet，重跑 `kubeadm reset -f`，清理 Kubernetes/etcd/kubelet/CNI 目录及 CNI 网卡，并验证管理配置和监听端口均已消失。
- 前台修复：kubelet 回滚 Playbook 改为容忍 API 注销失败，随后强制清理并检查本地 reset 后置条件。

### 残留修复 2：kubelet secret volume 挂载

- 症状：master-5 删除 `/var/lib/kubelet` 时报告 `Device or resource busy: coredns-token-tsxt5`。
- 原因：reset 后遗留的 kubelet secret volume 挂载。
- SSH 修复：仅在 `192.168.88.56` 按路径深度卸载 `/var/lib/kubelet` 下的挂载，再删除 kubelet、Kubernetes、etcd 和 CNI 状态目录。
- 验证：原前台回滚合同不变，重新审批并执行 kubelet 回滚 Run，六节点全部成功。

## 前台 Playbook 问题及修复

- Docker 首次验证失败：Docker Go template 被 Ansible 当成 Jinja。使用 `{% raw %}` 转义后重跑成功。
- kubeadm 1.17.5 的 `token create --print-join-command` 在此环境等待超时：控制面 API、etcd、controller-manager、bootstrap token 和 JWS 均健康。改为从前台托管 Playbook 读取 kubeadm 已生成的 bootstrap token，计算 CA hash，再执行标准 control-plane/worker join。
- Flannel 模板首次缺少 `pod_network_cidr`：在前台 Playbook 补入 `10.244.0.0/16` 后重跑成功。
- 修改回滚动作后，平台拒绝复用旧安装基线并报告合同摘要变化；重新执行安装验证建立新基线，再完成回滚验证，未绕过合同保护。
