# 2026-09-05 单 Ansible 作业验收记录

本轮完成组件 Role 单作业方案，并与同日场景生命周期改动联调。使用全新临时 SQLite 数据库、本机临时工作区和真实 Ansible；没有部署到现有测试环境、转换现有数据库、操作真实集群或提交、推送代码。

## 实现与恢复语义

- Release 必须具有安装、回滚及各自绑定的前后检查；检查按 Action ID 定位，可复用，同 Release 内绑定。Draft 可以不完整，执行与发布要求完整合同。
- 每个 Run 编译为一个正式 Ansible 作业，精确 Release 使用独立 Role；阶段使用独立 Play，handler 完成后才能进入后检查。同 Release 的不同节点分别执行。
- 同步控制点在持久化成功后放行，事件回调检查序号并脱敏。超时、取消、事件丢失、持久化失败和控制连接失效均停止后续阶段。
- 独立守护程序使用 Go 启动器提供的正式 Ansible 进程组，并在首个阶段放行前确认就绪。实际强制结束 Go 执行器后，Ansible 停止，后续阶段不启动；未确认的主体保留开始记录并拒绝不安全重试。已经发出的远端任务仍可能完成。
- 安装、回滚的主体成功与后检查通过分别记录。安全续跑建立新 Run，保留原始备份和来源关系；后检查失败只续跑后检查，继续前复核已完成依赖。场景验收续跑保留前次已完成的组件证据，不能重放旧分支。
- 场景预览导出与已生成 Run 的下载包均携带 CLI。部署构建同时提供平台和 CLI；缺少 CLI 会阻止生成不完整作业包。结果锁由操作系统释放，强制中断后无需删除锁文件。


`internal/ansible`、`internal/service`、`internal/jobcli` 三个包通过。实际覆盖：

- 两组件依赖、多主机组、同 Release 重复节点、参数隔离，以及 handler 完成顺序。
- 前检查、主体、handler、后检查失败；主机不可达、超时、取消；开始、结束和事件持久化失败；注入丢失真实 callback 事件。
- 场景前检查、主体、后检查和业务验收失败后的续跑或拒绝；安装主体只执行一次，原始备份不变。
- CLI 安装后检查失败、回滚前检查失败、回滚后检查失败及各自续跑。完整五次操作每次恰好一次正式调用，安装和回滚主体各执行一次。
- 强制结束独立 Go 执行器，确认 Ansible 退出、后续阶段没有启动、回执保留及结果锁自动释放。
- 凭据不进入导出包或公开日志；改动 Role 内容后拒绝运行。编译、合同和工作区测试另覆盖摘要及并发修改、重复检查、删除受引用检查等边界。
