## 已实现

| 需求 | 实现及核对结果 |
| --- | --- |
| CredentialRef 来源 | 环境页按当前权限列出组件、分支、精确版本、动作及场景业务验收声明；平台 SSH 用途独立显示。按来源去重，前三项展开、其余折叠。显示当前环境 Revision 与填写状态，继续脱敏，未解析真实 Secret。无可见声明不会提示可以删除。 |
| 组件环境参数来源 | 显示组件、分支、精确版本、参数名与当前环境 Revision。有合同查看权限时跳到该版本的参数区域；不同版本的同名参数分别保留。 |
| 平台类别布局 | “新增类别”位于环境适配维度区域；“新增子类别”预选当前父类别。真实父子类别和选项同框独占一行；环境变量字段、适配维度和主机组分别维护。新库初始化明确建立操作系统与版本关系，已有目录不按名称自动关联。 |
| 分支标签与创建入口 | 场景和组件首部展示适配标签。新增分支时选择并确认范围，未选择维度明确显示“不限制”；创建后固定。新增版本继承范围。保留发布、正式成功运行、业务验收和同分支演进门禁；新分支不继承历史证据。 |
| 合同编辑 | 参数合同、直接依赖各自编辑，另一部分只读；按编辑意图提交。依赖编辑可明确新增引用参数，移除映射时明确处理失效目标。定义代次在事务内复核，过期提交和无效映射均不留下部分修改。编辑中切换对象、分区或离开页面有未保存提醒。重复“配置合同”“编辑可见性与映射”入口已移除。版本与 Playbook 弹窗仅维护对应内容。 |
| 介质和镜像弹窗 | 表单与结果约 62:38，空结果收紧；已发布版本使用整行内容，保留来源修复入口。构建日志可展开为完整宽度、内部滚动；同时修复已结束构建原先不读取日志详情的问题。 |
| 执行阶段计数 | 共用计数组件、调用和专用样式已删除。预览、运行详情不再显示阶段数量相加公式；实际步骤、验收状态和作业包总步数保留。 |
| 目录归属 | 提供[主机基础目录和消费组件样板](../../examples/components/README.md)，包含公开路径、精确依赖映射、实际主机检查、基线捕获和逆序回退。导入仅创建草稿，未改绑现有组件目录。 |

## 数据边界与盘点

当前结构合同为 `clusterforge-v1-20260906-branch-scope`。新增发布线和场景父对象的固定适配范围，版本保留同值快照；初始化、API、Catalog 导出和恢复校验已同步。运行时没有通用迁移或从最新版本自动回填。

只读盘点工具为 `scripts/inspect-branch-scopes.py`，不会读取 CredentialRef 实际值或改写源库。

- [工作区旧库盘点](2026-09-06-existing-branch-inventory.json)：该历史库缺少当前结构合同和组件发布线身份。识别到 34 个旧组件分组，其中 3 组版本范围不同，不能据此推断当前分支；另有 5 个场景尚无固定范围。发现 6 项目录参数声明。该结果只作为后续分类依据。
- [此前本地浏览器夹具盘点](2026-09-06-prior-fixture-branch-inventory.json)：从已关闭且无 WAL 的旧夹具复制独立快照，只读检查。10 个分支尚未确定固定范围，其中一个场景的两个 Revision 范围不同。操作系统和操作系统版本仍为两个根类别，清单包含全部类别与选项关系；没有按名称自动归并。

以上均为本地资料，不代表测试主机上的实时数据库。旧转换工具已增加前置检查：缺少分支范围或同分支范围冲突时，在生成目标前拒绝执行。现有专项转换标志不能代替本次数据处理授权。

本次没有修改工作区旧库、此前夹具源库或远程数据库，没有迁入业务组件、重建测试环境、提交代码、推送或部署。后续环境交付须先对目标库重新盘点，并明确处理范围冲突和父子目录关系，再安排符合 V1 策略的数据切换。
