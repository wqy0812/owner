## 已直接修复的问题

1. **P1：收集到的 facts 随即被清空。** 生成的 Play 原先先自动 gather facts，再执行阶段重置的 `clear_facts`，动作访问不到本阶段刚收集的主机事实。改为关闭自动收集，重置后按声明显式运行 `ansible.builtin.setup`。真实 Ansible 回归同时验证需要 facts 的阶段和后续不收集 facts 的阶段。此修复已在批次 1 提交。
2. **P1：配置测试可以冒充安装发布证据。** `componentTestEvidence` 原先将 configure 加前后检查归为 `install_verify`，可能使从未测试 install 的初始版本通过发布门禁。现在只有完整 install 闭环提供安装证据，增加 configure-only 回归。修复保留在待提交的后端批次。
3. **P2：普通 HTTP 下无法新增验收或生成有效提交幂等键。** 两处 `crypto.randomUUID()` 在非安全上下文中不可用；预览可能留下空的提交键。统一使用 `crypto.getRandomValues` 生成 UUID，回归测试模拟没有 randomUUID 的浏览器，同时验证验收 ID 和提交键。修复保留在待提交的前端批次。
4. **P2：导入和复制 Role 后，检查任务引用仍指向旧文件。** 检查 Action ID 重新生成后，入口文件名同步改变，但 `include_tasks` / `import_tasks` 没有更新。现在仅改写任务语法中的文件操作数，保留模块数据和普通文本，更新动作摘要、文件摘要及工作区摘要。导入和复制两个回归均验证新引用与摘要；停用改写时两个回归均失败。修复保留在待提交的后端批次。
5. **P2：切换场景页签丢失未保存的验收内容。** 验收和升级页签切走后卸载组件，导致本地输入丢失。现在页签切换保留组件编辑状态，与目标集群页签一致。真实浏览器复现修复前丢失及修复后保留。修复保留在待提交的前端批次；此改动只处理同一版本内的页签切换。

## 尚需决定的保留策略

`internal/store/run_cleanup.go` 新增对操作回执和场景幂等提交记录的无条件引用保护。这能避免删除仍有恢复用途的历史，但也使已有回执的失败安装类 Run、已有幂等提交记录的失败场景 Run，即使已超过保留期且不再用于恢复，仍然无法清理。

建议延续现有保留期：到期后允许清理无恢复用途的失败记录，同时保留防重复提交凭证，并继续保护当前安装、恢复链、来源版本及续跑引用。另一种选择是明确这些 Run 永久保留、只允许归档。尚未收到此项决定，因此没有放宽删除条件。

平台执行、回执持久化、清理保护和依赖它们的 API / UI 暂缓提交。回执表与 Run 存在级联删除关系，不能单独漏掉清理保护后提交其余后端，以免留下可删除恢复证据的中间版本。备份及独立执行 CLI 也依赖同一当前契约，随该批次保留在工作区。
