## 用户确认的范围

旧库业务重置原先复制源 schema，生成的基础库不能交给当前合同程序使用。用户选择：支持旧库清空重建，只转换账号和基础目录，不恢复旧业务与 Run。

据此实现 `foundation-snapshot`：读取旧 V1 库，用当前 schema 新建数据库，仅复制账号、分类/选项和环境变量字段定义。目录父子关系、退役状态和用户身份保留；组件、场景、环境、Run、会话、旧全局参数定义/默认值不进入新库，自动归档/清理保持关闭。缺少必要列、活动任务、非法目录或已有目标文件会阻断。源库不原地修改；原合同业务恢复库只用于部署失败回退。

部署重置模式固定身份初始化配置，避免空业务库被示例数据填充。普通启动仍严格拒绝旧合同，不新增运行时双读或旧业务迁移。此项判断已落实，没有遗留待决定的代码问题。
