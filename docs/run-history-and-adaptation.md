# 适配标签、直接引用与 Run 历史

组件分支和场景分支在创建时确定多选适配范围，此后固定；版本继承同值快照，环境 Revision 填写单选实际值。同分类多个值取或，不同分类取且。组件未声明表示不限；组件有限制时场景必须补选，环境缺失要求值时不匹配。草稿可暂存待解决的适配问题；新增分支改变范围后须调整复制的组件。缺项或冲突均不能测试、发布、执行。已有分支不能修改标签；如需改变范围，应新增独立分支，不继承原有测试证据。运行时由精确组件 Release 依赖表达，不再维护 Docker/containerd 适配分类或运行时测试矩阵。

组件详情的“谁用了我”仅向该组件 Owner 和平台管理员开放，统计已保存的直接引用。默认全部上游版本、排除废弃版本和旧场景 Revision；历史开关可以查看保留的历史引用。私有引用仅展示摘要，无详情权限不提供跳转。

## 归档与清理

运行中心提供当前记录、历史归档和全部记录。管理员可归档成功记录，或预览并清理超过保留期限且没有安装、续跑、回滚引用的失败记录。批量操作最多 100 条，只处理明确选中的当前页记录。取消、拒绝、中断及活动记录均不清理。期限从 finishedAt 计算，缺少结束时间跳过。

场景版本来源、环境基线、幂等提交、基线恢复证据及升级备份引用链也受清理保护。场景业务验收作为独立步骤随 Run 保留；新合同的失败场景作业不能使用通用续跑绕过部分变更状态。恢复后通过独立的基线复核证明实际状态，历史 Run 和动作回执保持不变，详见[场景生命周期](scenario-lifecycle.md#基线证据和恢复)。

成功归档保留 Run、执行快照、步骤、审批和业务引用，只移除已验证转存的日志；下载包包含 manifest.json、run.json、run_steps.json、approvals.json、logs.ndjson，保存校验值、日志顺序及数量。归档失败保留在线日志，管理员可重试。失败清理不可恢复，事务内保留不可变审计和最小历史标记；历史标记用于访问权限、生命周期保护及工作台排序，不作为成功证据。

## 配置与自动处理

服务环境变量 `CLUSTERFORGE_RUN_ARCHIVE_DIR` 指向独立持久化目录的绝对路径，不能放在程序发布目录内。未配置时归档不可用，普通 Run 执行不受影响。目录权限按服务账号配置。

管理员在运行中心“运行历史管理”配置自动归档和自动清理；初始都关闭，默认 90 天，允许 1–36500 天。启动补查后每日扫描，按结束时间推进，每轮最多扫描 100 条并保留游标（两个自动开关均启用时各 50 条）；受保护条目不会持续阻塞后续候选，扫描完一遍后重新检查。自动清理逐条记录成功、跳过原因及失败结果。归档任务串行执行，使用可续租任务资格；过期任务可接管。只有文件验证、落盘和最终数据库事务全部成功才移入历史归档。

先完成少量归档、下载和备份恢复演练，再由管理员开启自动处理。本次实施不启用测试环境的自动处理。

## 完整备份及 Git 备份

Git 备份能力保留，可在后续重新启用。Catalog Git 内容仍是发布定义，运行历史以完整 SQLite 快照及对应归档目录为准；完整备份清单记录并验证其全部归档文件。仅复制数据库或旧程序发布目录不足以恢复已归档日志。

Git 暂时停用时，可使用以下独立入口（均只写入新的目标目录）：

```sh
clusterforge-backup database history-snapshot --db /path/platform.db --archive-dir /persistent/run-archives --target /backup/new-history
clusterforge-backup database history-verify --db /backup/new-history
clusterforge-backup database history-restore --db /backup/new-history --target /restore/new-history
```

恢复结果包含 platform.db、archives 和校验清单；先验证，在维护窗口配置恢复后的数据库与归档目录，再启动平台。归档文件缺失或损坏会明确拒绝下载，不展示为空日志。不提供单个 Run 归档恢复、成功 Run 永久删除、压缩包自动过期或自动整库压缩。

运行时只接受当前数据库合同，不自动兼容旧库。现提供从 Role Job 合同到场景生命周期合同的[保留历史离线转换](scenario-lifecycle.md#保留历史的离线数据库转换)：只读源库，生成新库及配套工作区，保留业务与历史，不补造验收或升级证据。转换与部署须另行安排。经明确授权的业务重置仍可只把旧 V1 账号和基础目录转换到当前 schema 的新库，具体见[业务重置流程](catalog-backup-and-restore.md#业务清空专用备份不含-run-历史)；这种重置不保留旧业务，不能代替完整转换。
