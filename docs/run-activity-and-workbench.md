# Run 活动读取与工作台查询合同

本轮数据库合同：`clusterforge-v1-20260906-workbench-run-observations`。只创建新的精确合同，不提供旧库迁移、历史回填或兼容分支；新合同保留 Run 历史、归档、清理以及清理后的最小历史标记。实施不包含现有环境重建或部署。

## 场景编辑基线

保存请求和修改判定共同使用 `web/src/types/scenarioGraphContent.ts`。比较持久化节点、位置、名称、Release、动作、参数、依赖来源、连线和环境约束；选择状态、尺寸、Owner 展示信息和合同可见性不参与比较。

对象键递归排序，节点和边按稳定 ID 排序，环境约束按多选集合排序。参数中的普通数组保留顺序。空参数和依赖来源归一化为 `{}`。服务端持久化响应建立基线；仅键顺序变化不产生修改，真实依赖变化仍要求保存。合同缺失或延迟时保留已有边和参数。

保存继续携带 `expectedDigest`。保存期间的新编辑保留并继续显示未保存；切换 Revision、身份或重新载入后的旧响应不覆盖当前编辑器。测试前保存规则不变。

## 等待状态表

`run_waiting_observations` 的主键是 `(run_id, step_id, host, task)`，保存最新 `log_id` 和经过结构校验的 waiting 事件 JSON。`run_logs` 插入触发器在同一事务维护投影：waiting 覆盖，result 删除对应等待项；普通日志、无效 JSON、无效结构和受保护结果只作为日志保留。

先后顺序由数据库日志 ID 决定。Run 终态触发清理，终态迟到日志不能重新产生等待。Run 删除和归档删除在线日志时通过外键清理派生状态。查询只搜索投影主键范围；读取失败返回错误，客户端保留旧值并提供重试。

## Activity 接口

`GET /api/v1/runs/{id}/activity` 使用现有 Run 可见性规则，返回：

```text
{ runId, status, logs, nextAfterId, hasMore, waitingObservations, archived }
```

- 省略 `afterId`：最近 200 条日志，ID 升序。
- 非负 `afterId`：返回 ID 大于游标的日志。`limit` 默认 500，范围 1–2000。
- `hasMore=true`：继续按 `nextAfterId` 读取。空页保持输入游标。
- 日志可没有 `stepId`，例如系统日志；客户端将其规范为无步骤日志。
- `waitingObservations` 是脱敏后的 waiting 事件数组，事件包含 `stepId`、可选 `host/task` 和 `result.waiting`。
- 状态、归档标记、日志及等待项来自同一只读数据库快照。
- 归档后返回 `archived=true` 和空在线日志，完整内容继续由现有下载接口提供。

普通详情接口不再装配日志尾部和等待项。原始日志仍完整保留在数据库或归档包中。

## 浏览器刷新

`run.log` 仅发布 `{runId,logId}`，且在日志提交成功之后发布。事件分发器以 Run ID 订阅，不更新应用上下文和全局 `runs` 刷新标记。当前 Run 每 400 毫秒合并补读；每个查询最多一个在途请求，其间事件合并为后续读取。

首次取日志尾部，重连按已有游标补拉并对齐业务状态；终态事件到达后补读。可见页面每 10 秒补读已知活动数据，隐藏暂停，恢复可见立即对齐。选中 Run 的状态变化会刷新相关业务查询，即使终态 SSE 丢失也能恢复。组件当前工作项和证据弹窗发现活动 Run 时也有补读。

浏览器按日志 ID 去重、排序并最多保留最近 2000 条。切换 Run、身份和页面卸载时取消旧请求并释放订阅。完整日志使用现有下载接口。

## 工作台查询

`GET /workbench` 保持原工作项、优先级、原因、入口、资产统计和权限规则。专用查询按角色读取：

| 角色 | 读取范围 |
|---|---|
| 组件 Owner | 自有组件身份、Draft 合同、所需依赖及摘要匹配的验证记录 |
| 场景 Owner | 自有场景身份、需要处理的当前 Revision、锁定合同和测试证据 |
| 环境 Owner | 当前环境配置、最新检查摘要、活动 Run、审批与灾备状态 |
| 平台管理员 | 待审核 Release 的元数据和提交摘要 |

通用 Run 查询先选出全部可见活动项及各业务分组的最新记录，再核验待展示的失败项。清理记录参与最新记录判断，防止旧失败重新出现。成功等仅用于压制旧失败的记录不装配执行快照。

组件证据使用合同摘要索引。场景证据按 Revision、摘要、状态和时间缩小范围，以 64 条为一批核验锁定 Release，直到找到需要的有效证据或候选耗尽；没有最近 N 条截断。候选相关合同、名称、Owner 和失败节点批量读取。缓存只在当前请求内有效，保留现有 Readiness 和场景校验规则；没有跨请求缓存或待办持久化表。

性能与回归证据见 [实施验收记录](records/2026-09-07-performance-validation.md)。
